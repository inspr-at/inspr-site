Ch 01 · The mission

The premise, briefly.

Most platforms are built on a substrate. INSPR is built between substrates. Whichever agent harness, model provider, no-code editor, or paradigm is dominant in 2026 will not be the same in 2030 — and anything built downstream of one of those goes with it.

INSPR sits upstream. It is the durable place where your wants live, get refined, and turn into things — independent of which specific tool happens to be carrying the weight today. Plural entrypoints around the edges. One declarative truth in the middle.

Someone whose collection has outgrown its spreadsheet. An operator who wants to declare every byte across a hundred hosts. Both are first-class users of the same platform. Neither is the primary persona to the exclusion of the other.

Ch 02 · Pluralism

Two axes. One canonical artifact.

A single fixed abstraction excludes one population. A single fixed harness excludes most of the ecosystem. The architectural answer is plural along two axes — and byte-identical artifacts however you got there.

Axis · α

Harness pluralism

Multiple peer agent harnesses — Claude Code, opencode, Flue, a future local-model harness — sit behind an INSPR-defined protocol. None is the foundation of the platform. Each adapter is welcomed; none is owed.

  • privacy & IP — work that can’t leave the machine
  • availability — when a hosted vendor goes down or sanctions you
  • local-model preference — running fully on your own iron

Axis · β

Abstraction pluralism

Multiple entrypoints — conversational agent, declarative authoring, direct verb calls — produce the same canonical artifacts. The agent never bypasses declarative. The user can always bypass the agent.

  • collector — past what a spreadsheet can hold
  • operator — declares every byte; reviews like a PR
  • both — first-class on the same substrate

Ch 03 · The contract

Two rules. Bound the design space cleanly.

Any agent acting on an INSPR-managed fleet is bound by two rules. Rule 1 alone would let the platform be agent-driven but non-overridable. Rule 2 alone would let agents do anything, since users can technically override afterward. Together they leave no room for either failure mode.

  1. Rule 01

    The agent never imperatively bypasses declarative.

    Every effect on the fleet is either a draft of a declarative artifact — nixcfg edit, agenix recipient list, plan YAML — or a call to a typed Bosun verb. Direct imperative ops (ad-hoc SSH, file edits outside source-of-truth, anything not auditable from git log) are forbidden for agents.

    If something can only be done imperatively today, that is a Bosun-verb gap to file. Not a license to improvise.

  2. Rule 02

    The user can always bypass the agent.

    Every artifact the agent produces is in the same canonical format an expert would hand-author: plain Nix, plain YAML or JSON for verb arguments, plain Bosun verb invocations.

    Hand-editing the draft, skipping the agent entirely, or running the same verbs from a shell are first-class paths — not fallbacks, not power-user flags, not undocumented escape hatches. There is no agent-only privileged channel.

The currency of fleet operations is declarative artifacts and typed verbs. Humans and agents both spend it. Nobody has a private mint.

Ch 04 · The artifacts

Concrete things, named plainly.

What INSPR is, by the things it ships. Status is honest: live means running daily, in flight means exists but not at scale, forthcoming means designed but not yet built.

  1. Paimos

    live

    Project management upstream of agents

    A typed CLI and service for issues, anchors, plans, and manifests. The first product to live inside INSPR. JSON-everywhere by default; the tool an agent and an operator can both reach for without reading different docs.

    paimos.com ↗

  2. FleetCom

    in flight

    Declarative fleet management plane

    The control plane that keeps an INSPR fleet in sync. Host-class profiles, declarative apply, and a registry of typed verbs. Runs at fleet.barta.cm in the personal context; opens to BYTEPOETS and family contexts as their adapter shape stabilises.

  3. Bosun

    forthcoming

    Per-host agent under FleetCom

    One process per fleet member. The outward-facing API is a typed, versioned verb set with --json everywhere — the contract any harness adapter targets. Verbs evolve under SemVer; adapters declare which version they expect.

  4. inspr-modules

    live

    Public flake of reusable modules

    Mechanics public, values per-context. The same module — Tailscale-on-Headscale, agenix bootstrap, dev-tool bundles — composes into a personal nixcfg, a BYTEPOETS internal flake, a family flake, future paid contexts. Pattern β, validated by two structurally-different consumers.
