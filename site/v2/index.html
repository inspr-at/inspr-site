Ch 01 · The mission

The premise, briefly.

Most platforms are built on a substrate. INSPR is built between substrates. Whichever agent harness, model provider, no-code editor, or paradigm is dominant in 2026 will not be the same in 2030 — and anything built downstream of one of those goes with it.

INSPR sits upstream. It is the durable place where your wants live, get refined, and turn into things — independent of which specific tool happens to be carrying the weight today. Plural entrypoints around the edges. One declarative truth in the middle.

Someone whose collection has outgrown its spreadsheet. An operator who wants to declare every byte across a hundred hosts. Both are first-class users of the same platform.

Ch 02 · Pluralism

Two axes. One canonical artifact.

A single fixed abstraction excludes one population. A single fixed harness excludes most of the ecosystem. The architectural answer is plural along two axes — and byte-identical artifacts however you got there.

Axis · α

Harness pluralism

Multiple peer agent harnesses sit behind an INSPR-defined protocol. None is the foundation. Each adapter is welcomed; none is owed.

Axis · β

Abstraction pluralism

Multiple entrypoints produce the same canonical artifacts. The agent never bypasses declarative. The user can always bypass the agent.

Ch 03 · The contract

Two rules. Bound the design space cleanly.

Any agent acting on an INSPR-managed fleet is bound by two rules. Together they leave no room for either failure mode.

  1. Rule 01

    The agent never imperatively bypasses declarative.

    Every effect on the fleet is either a draft of a declarative artifact — nixcfg edit, agenix recipient list, plan YAML — or a call to a typed Bosun verb. Direct imperative ops are forbidden for agents.

    If something can only be done imperatively today, that is a Bosun-verb gap to file. Not a license to improvise.

  2. Rule 02

    The user can always bypass the agent.

    Every artifact the agent produces is in the same canonical format an expert would hand-author: plain Nix, plain YAML or JSON, plain Bosun verb invocations.

    Hand-editing the draft, skipping the agent entirely, or running the same verbs from a shell are first-class paths — not fallbacks, not power-user flags.

The currency of fleet operations is declarative artifacts and typed verbs. Humans and agents both spend it. Nobody has a private mint.

Ch 04 · The artifacts

Concrete things, named plainly.

What INSPR is, by the things it ships. Status is honest: live means running daily, in flight means exists but not at scale, forthcoming means designed but not yet built.

  2. FleetCom

    in flight

    Host-class profiles, declarative apply, a registry of typed verbs. Public source. Runs in the personal context today.

  3. Bosun

    forthcoming

    Per-host agent under FleetCom

    One process per fleet member. Outward-facing API is a typed, versioned verb set with --json everywhere — the contract any harness adapter targets.

  4. inspr-modules

    live

    Public flake of reusable modules

    Mechanics public, values per-context. Same module composes into personal nixcfg, company-internal, family, future paid contexts.
